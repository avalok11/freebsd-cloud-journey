# Шеллы: разделение ролей — tcsh для интерактива, bash+Python для скриптов

**Время чтения:** ~4–5 минут
**Фаза:** 0 (вводная теория перед практикой)
**Цель:** раз и навсегда разделить «где администратор работает» и «на чём пишется автоматизация».

---

## 1. Два мира: интерактивный vs скриптовый

**Интерактивный шелл** — то, что видно при открытии терминала и вводе команд.
**Скриптовый язык** — то, на чём пишется автоматизация, выполняемая без участия администратора.

Это **разные задачи** с разными требованиями. Для каждой — свой инструмент.

## 2. tcsh/csh — интерактивный шелл

**Почему tcsh/csh исторически нативен для FreeBSD:**

- До FreeBSD 13.x `csh` был дефолтным шеллом для root.
- В книге «Absolute FreeBSD» (Lucas) примеры даны на csh — это «книга для админа FreeBSD».
- Во FreeBSD Handbook многие секции по интерактивной работе написаны на csh.
- Синтаксис для интерактива **удобный**: history-механизм, автодополнение, control-A/E для навигации по строке.

**Что tcsh умеет хорошо:**

- `set foo = bar` — присваивание.
- `if ( -f /etc/passwd ) then ... endif` — управляющие конструкции.
- `foreach i ( *.txt )` — цикл по списку.
- `setenv PATH /usr/local/bin:$PATH` — переменные окружения.
- Встроенный history с поиском по Ctrl-R.

**Что tcsh умеет плохо:**

- Обработка пайпов с ошибками — не POSIX-совместимо.
- Массивы — неудобно.
- Functions (функции) — слабо.
- Совместимость с другими скриптами — никакая.
- В документации и примерах из мира автоматизации tcsh не встречается.

## 3. bash (POSIX sh) — скриптовый шелл

**Почему bash/POSIX sh:**

- **POSIX-совместимо.** Весь мир автоматизации: Ansible, Bastille, vm-bhyve, FreeBSD Handbook, все готовые скрипты — POSIX sh/bash.
- **Читается в любой документации.** Любой туториал на serverfault, в Handbook, в readme на GitHub — на bash.
- **Идемпотентность.** Bash-скрипт при правильном написании можно запускать много раз, результат одинаков.
- **Совместимость с Ansible.** Ansible использует POSIX sh для подключения к управляемым нодам.

**Что bash умеет хорошо:**

- `if [ -f /etc/passwd ]; then ... fi` — POSIX-стиль.
- `for i in *.txt; do ... done` — цикл.
- `set -euo pipefail` — строгая обработка ошибок.
- Массивы: `arr=(a b c)`, `${arr[0]}`.
- Functions: `my_func() { ... }`.
- Подстановки: `$(command)`, `${var}`.

**Shebang для скриптов:**

```bash
#!/bin/sh           # POSIX sh, максимально совместимо
#!/usr/bin/env bash # bash-специфичные фичи
```

## 4. Python — для сложной логики

**Когда Python вместо bash:**

- Логика больше 20 строк.
- Работа с JSON, YAML, API.
- Циклы с нетривиальной обработкой ошибок.
- Парсинг логов, метрик.
- Сетевые вызовы, библиотеки.

**Примеры задач в этом проекте:**

- Парсинг JSON-ответа от Ansible в скрипте деплоя.
- Анализ метрик Prometheus для алертинга.
- Скрипт, собирающий данные с нескольких серверов и формирующий отчёт.
- Интеграция с Telegram API для уведомлений.

**Shebang:**

```python
#!/usr/bin/env python3
```

## 5. Почему НЕ tcsh в скриптах

**Сравнение одного и того же скрипта:**

**bash (POSIX-совместимо, читается везде):**
```bash
#!/bin/sh
if ! pkg info -q nginx > /dev/null 2>&1; then
    logger "nginx not installed, installing"
    pkg install -y nginx
    sysrc nginx_enable=YES
    service nginx start
fi
```

**tcsh (нигде в продакшене так не пишут):**
```tcsh
#!/bin/tcsh
set pkg_check = `pkg info -q nginx`
if ( $? != 0 ) then
    logger "nginx not installed, installing"
    pkg install -y nginx
    sysrc nginx_enable=YES
    service nginx start
endif
```

Bash-вариант встречается в **любом** учебнике, **любой** официальной документации, **любом** скрипте на GitHub. tcsh-вариант — только в музее.

**Реальные проблемы с tcsh в скриптах:**

1. **Ansible.** Модули ожидают POSIX sh на управляемой ноде. tcsh ломает пайпы, обработку stderr.
2. **Bastille, vm-bhyve.** Все management-скрипты на bash.
3. **Переносимость.** Скрипт на tcsh работает только на FreeBSD. Скрипт на bash — везде.
4. **Читаемость.** Коллега (или автор через год) потратит время на расшифровку.
5. **Onboarding.** Появление Linux-админа в команде — tcsh его остановит.

## 6. Когда tcsh уместен

**Только в интерактиве.** Открыт терминал, вводятся команды — tcsh. Скрипты не пишутся.

**В этом проекте:**

- Login shell на FreeBSD — `csh` или `tcsh`.
- Любой скрипт в `infra-configs`, `bastille`, ansible — на bash/POSIX sh.
- Скрипты сложнее 20 строк — на Python.

**Это рабочий компромисс:**

- Зона комфорта в интерактиве сохраняется.
- Скрипты пишутся в стандартной экосистеме.
- Никаких сюрпризов с Ansible.

## 7. Настройка по умолчанию в стенде

**На FreeBSD-нодах (через Ansible):**

```yaml
# /etc/rc.conf
defaultrouter="..."

# /etc/passwd
alexey:*:1000:1000:Alexey:/home/alexey:/bin/tcsh
```

**В скриптах автоматизации (Ansible-роли, Bastillefile, мониторинг):**

```bash
#!/bin/sh
# или
#!/usr/bin/env bash
```

**Скрипты обработки данных:**

```python
#!/usr/bin/env python3
```

## 8. Чего НЕ делать

**Не рекомендуется:**

- Писать `#!/bin/tcsh` в скриптах. Вообще никогда.
- Использовать `csh` для cron-задач. Только sh/bash.
- Переписывать существующие bash-скрипты на tcsh «потому что FreeBSD».

**Рекомендуется:**

- tcsh для интерактива.
- bash/POSIX sh для скриптов автоматизации — стандарт.
- Python для сложной логики.
- **Shebang в скриптах ВСЕГДА `#!/bin/sh` или `#!/usr/bin/env bash` или `#!/usr/bin/env python3`**. Никогда `#!/bin/tcsh`.
