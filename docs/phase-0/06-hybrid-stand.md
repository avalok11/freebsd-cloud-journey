# Гибридный стенд: локально + Selectel, динамический IP, рабочая станция

**Время чтения:** ~4–6 минут
**Фаза:** 0 (вводная теория перед практикой)
**Цель:** понять архитектуру нашего стенда, чтобы не пытаться растянуть кластер домой и не удивляться почему ничего не работает.

---

## 1. Почему гибрид

У нас два окружения с разными ролями:

| Окружение | Где | Зачем |
|---|---|---|
| **Локальный стенд** | UTM на Mac M4 (FreeBSD arm64, Debian arm64) | Эксперименты, обучение, можно ломать |
| **Удалённый стенд** | Selectel VPS (FreeBSD amd64, Linux) | Production-like, реальные IP, реальная сеть |
| **Рабочая станция** | Mac M4 (сам ноутбук) | Ansible, ssh-клиент, документация, репозитории |

**Это не «у нас две среды, потому что две»**. Это **намеренное разделение**:
- Локально — чтобы быстро проверять гипотезы, не платить за облако каждую минуту.
- В Selectel — чтобы видеть реальное поведение: сетевые задержки, биллинг, реальные IP.
- Ноутбук — чтобы быть **оператором** инфраструктуры, а не её частью.

## 2. Почему ноутбук НЕ часть кластера

**Исторически** многие админы делали «домашний сервер» — ставили FreeBSD на старый комп, поднимали там jail-ы, делали его частью инфраструктуры. Это **плохая модель** в 2026 году:

1. **Домашний интернет канал** — асимметричный, нестабильный, динамический IP.
2. **Электричество** — отключения, скачки напряжения.
3. **Шум, пыль, охлаждение** — домашний сервер в шкафу через 2 года превращается в пылесос.
4. **Безопасность** — домашний роутер = периметр, не контролируемый.
5. **Доступность** — ты не дома = инфраструктура недоступна.

**Правильная модель — «всё в облаке или в дата-центре»**, а твой ноутбук — это **операторская консоль** для управления. Как в enterprise: у сисадмина нет своего сервера в серверной, у него есть рабочее место с VPN и SSH.

**Когда дорастём до реального заказчика:**
- Заказчик даёт тебе **VPN-доступ** к своей инфраструктуре.
- Ты сидишь дома, в офисе, в кафе — везде, где есть интернет.
- Подключаешься через VPN, дальше SSH.
- Никакого «мой домашний сервер должен быть включён».

## 3. Динамический IP — почему это не проблема

**Что такое динамический IP:**
- Провайдер выдаёт тебе адрес из пула при каждом подключении.
- У тебя дома IP меняется при перезагрузке роутера, раз в сутки, раз в неделю — как у провайдера настроено.
- Может быть «серый» IP (10.x.x.x, 100.64.x.x) — тогда ты вообще за NAT провайдера.

**Почему это не мешает нашему стенду:**

1. **Исходящие подключения работают всегда.** Ты с ноутбука подключаешься к Selectel-серверам по ssh — твой IP неважен, Selectel видит что пришёл ssh-клиент и отвечает.

2. **SSH-ключи не привязаны к IP.** Аутентификация по ключу — без разницы откуда ты подключаешься. Ограничения `from=` в authorized_keys — это IP **назначения** (кто может подключаться к этой ноде), а не источника твоего ноута.

3. **Git push в GitHub/Gitea** — то же самое, исходящее соединение. Твой IP не важен.

4. **Обратный трафик нам не нужен.** Никто не подключается к твоему ноутбуку из Selectel. Только ты к ним.

**Когда динамический IP стал бы проблемой:**
- Если бы ты хотел, чтобы **Selectel сам ходил к тебе домой** (например, бэкап-сервер у тебя дома). Но у нас бэкапы идут в Selectel → Selectel, не домой.
- Если бы ты хотел поднять у себя публичный web-сервер. Но у нас в Selectel.

**Если захочешь постоянный доступ из дома:**
- Поднимаешь на одной из Selectel-нод **WireGuard VPN**.
- Подключаешь ноутбук как клиент.
- Получаешь «статичный» IP в виртуальной сети WireGuard.
- Но это не нужно для нашего обучения.

## 4. Как настроен рабочий процесс

**На Mac M4:**

```
~/projects/freebsd-cloud-journey/    # GitHub, публичный репо
~/.ssh/freebsd_lab                   # приватный ключ
~/.ssh/config                        # алиасы для всех нод
```

**`~/.ssh/config` (пример):**
```
Host fbsd-arm
    HostName 192.168.64.10
    User alexey
    IdentityFile ~/.ssh/freebsd_lab
    IdentitiesOnly yes

Host fbsd-1-sel
    HostName 195.201.xxx.xxx
    User alexey
    IdentityFile ~/.ssh/freebsd_lab
    IdentitiesOnly yes
    # TOTP через Yandex Key
```

**После этого:**
```bash
ssh fbsd-1-sel
# вместо
ssh -i ~/.ssh/freebsd_lab alexey@195.201.xxx.xxx
```

## 5. Архитектура подключений

```
[Mac M4 / рабочая станция]
  ├─ SSH-клиент + Ansible
  ├─ Git push в GitHub (freebsd-cloud-journey)
  ├─ Git push в Gitea (infra-configs, после Фазы 4)
  └─ SSH по ключу ко всем нодам

[UTM локально]
  ├─ fbsd-arm.lab.local (FreeBSD 15.1 arm64)
  └─ deb-arm.lab.local (Debian 12 arm64)
     ↑ подключение с Mac M4 по host-only сети

[Selectel VPS]
  ├─ fbsd-1-sel.lab.local (FreeBSD 14.3 amd64)
  ├─ fbsd-2-sel.lab.local
  ├─ fbsd-3-sel.lab.local
  ├─ deb-1-sel.lab.local
  └─ gitea.lab.local (после Фазы 4)
     ↑ подключение с Mac M4 по публичному IP
```

**Нет обратного трафика. Нет зависимости от твоего IP.**

## 6. Что будет, когда дорастём до заказчика

**Сейчас (обучение):**
- Ты один, всё в Selectel, бюджет 10к/мес.
- Локальные ВМ для экспериментов.

**Через 4–6 месяцев (первый заказчик):**
- Инфраструктура заказчика в его дата-центре или его VPS.
- Доступ по VPN + SSH-ключ.
- Ты из дома подключаешься к его нодам — точно так же как к Selectel.
- Никаких «домашних серверов», всё профессионально.

**Через год (3–5 заказчиков):**
- У каждого своя инфраструктура.
- У тебя — `~/.ssh/config` с десятками хостов.
- Ansible-инвентарь по заказчикам.
- Git push в их Gitea-инстансы.
- Ты как «внешний DevOps» — без своего железа.

## 7. Преимущества этой модели

| Преимущество | Как проявляется |
|---|---|
| **Твоя безопасность** | Домашний IP не светится в публичных логах заказчика |
| **Твоя свобода** | Работаешь из любой точки мира, где есть интернет |
| **Разделение** | Ломаешь локально — не роняешь прод. Роняешь прод — не страдает локальный стенд |
| **Воспроизводимость** | Всё в git, можно клонировать инфру, нанять помощника |
| **Соответствие практикам** | Это как работает enterprise DevOps |

## 8. Типичные ошибки

**«А давай я дома подниму ещё одну ноду и включу в кластер»:**
Не надо. Домашний канал и uptime не соответствуют продакшену. Будет вечно «что-то отваливается, наверное мой NAT глючит».

**«А давай настрою DynDNS и буду ходить на домашний сервер»:**
Не надо. Это 2010 год. В 2026 есть VPN и облака.

**«А зачем мне VPN, если у меня и так SSH-ключ»:**
Когда заказчик скажет «вот тебе наш периметр, подключайся через WireGuard», ты будешь рад что умеешь.

**«А давай я в Selectel куплю IP за 200 ₽ и буду с него ходить домой»:**
Можно, но зачем. Selectel-нода — это уже удалённый хост с белым IP. Всё что тебе нужно, ты делаешь на ней.
