# Гибридный стенд: локально + Selectel, динамический IP, рабочая станция

**Время чтения:** ~4–5 минут
**Фаза:** 0 (вводная теория перед практикой)
**Цель:** понять архитектуру стенда и избежать распространённой ошибки с «домашним сервером».

---

## 1. Почему гибрид

Используются три окружения с разными ролями:

| Окружение | Где | Зачем |
|---|---|---|
| **Локальный стенд** | UTM на Mac M4 (FreeBSD arm64, Debian arm64) | Эксперименты, обучение, можно ломать |
| **Удалённый стенд** | Selectel VPS (FreeBSD amd64, Linux) | Production-like, реальные IP, реальная сеть |
| **Рабочая станция** | Mac M4 (сам ноутбук) | Ansible, ssh-клиент, документация, репозитории |

Это **намеренное разделение**:
- Локально — быстрая проверка гипотез, без оплаты облака каждую минуту.
- В Selectel — реальное поведение: сетевые задержки, биллинг, реальные IP.
- Ноутбук — **оператор** инфраструктуры, а не её часть.

## 2. Почему ноутбук НЕ часть кластера

**Исторически** многие админы делали «домашний сервер» — ставили FreeBSD на старый комп, поднимали jail-ы, делали его частью инфраструктуры. Это **плохая модель** в 2026 году:

1. **Домашний интернет-канал** — асимметричный, нестабильный, динамический IP.
2. **Электричество** — отключения, скачки напряжения.
3. **Шум, пыль, охлаждение** — домашний сервер в шкафу через 2 года превращается в пылесос.
4. **Безопасность** — домашний роутер = периметр, не контролируемый.
5. **Доступность** — администратор не дома = инфраструктура недоступна.

**Правильная модель — «всё в облаке или дата-центре»**, а ноутбук — **операторская консоль** для управления. Как в enterprise: у сисадмина нет своего сервера в серверной, есть рабочее место с VPN и SSH.

**Когда дорастёт до реального заказчика:**
- Заказчик даёт **VPN-доступ** к своей инфраструктуре.
- Администратор работает из дома, офиса, кафе — везде, где есть интернет.
- Подключение через VPN, дальше SSH.
- Никаких «домашних серверов», всё профессионально.

## 3. Динамический IP — почему это не проблема

**Что такое динамический IP:**
- Провайдер выдаёт адрес из пула при каждом подключении.
- IP меняется при перезагрузке роутера, раз в сутки, раз в неделю — зависит от настроек провайдера.
- Может быть «серый» IP (10.x.x.x, 100.64.x.x) — адрес за NAT провайдера.

**Почему это не мешает стенду:**

1. **Исходящие подключения работают всегда.** Подключение с ноутбука к Selectel-серверам по ssh — IP не важен, Selectel видит ssh-клиент и отвечает.

2. **SSH-ключи не привязаны к IP.** Аутентификация по ключу — без разницы, откуда подключение. Ограничения `from=` в authorized_keys — это IP **назначения** (кто может подключаться к ноде), не источника.

3. **Git push в GitHub/Gitea** — исходящее соединение. IP не важен.

4. **Обратный трафик не нужен.** Никто не подключается к ноутбуку из Selectel. Только к Selectel.

**Когда динамический IP стал бы проблемой:**
- Потребность в **обратном подключении** Selectel к ноутбуку (например, бэкап-сервер дома). В этом проекте бэкапы идут Selectel → Selectel, не домой.
- Потребность в **публичном web-сервере дома**. В этом проекте — в Selectel.

**Если потребуется постоянный доступ из дома:**
- На одной из Selectel-нод поднимается **WireGuard VPN**.
- Ноутбук подключается как клиент.
- Получается «статичный» IP в виртуальной сети WireGuard.
- Для обучения это не нужно.

## 4. Настройка рабочего процесса

**На Mac M4:**

```
~/projects/freebsd-cloud-journey/    # GitHub, публичный репо
~/.ssh/freebsd_lab                   # приватный ключ
~/.ssh/config                        # алиасы для всех нод
```

**Пример `~/.ssh/config`:**

```
Host fbsd-arm
    HostName 192.168.64.10
    User avalok11
    IdentityFile ~/.ssh/freebsd_lab
    IdentitiesOnly yes

Host fbsd-1-sel
    HostName 178.72.xxx.xxx
    User avalok11
    IdentityFile ~/.ssh/freebsd_lab
    IdentitiesOnly yes
    # TOTP через Yandex Key
```

**После настройки:**

```bash
ssh fbsd-1-sel
# вместо
ssh -i ~/.ssh/freebsd_lab avalok11@178.72.xxx.xxx
```

## 5. Архитектура подключений

```
[Mac M4 / рабочая станция]
  ├─ SSH-клиент + Ansible
  ├─ Git push в GitHub (freebsd-cloud-journey)
  ├─ Git push в Gitea (infra-configs, после Фазы 4)
  └─ SSH по ключу ко всем нодам

[UTM локально]
  ├─ fbsd-arm.lab.local (FreeBSD 15.1 arm64)
  └─ deb-arm.lab.local (Debian 13.6 arm64)
     ↑ подключение с Mac M4 по host-only сети

[Selectel VPS]
  ├─ fbsd-1-sel.lab.local (FreeBSD 14.3 amd64)
  ├─ fbsd-2-sel.lab.local
  ├─ fbsd-3-sel.lab.local
  ├─ deb-1-sel.lab.local
  └─ gitea.lab.local (после Фазы 4)
     ↑ подключение с Mac M4 по публичному IP
```

**Нет обратного трафика. Нет зависимости от IP ноутбука.**

## 6. Эволюция при росте до заказчика

**Сейчас (обучение):**
- Один администратор, всё в Selectel, бюджет 10к/мес.
- Локальные ВМ для экспериментов.

**Через 4–6 месяцев (первый заказчик):**
- Инфраструктура заказчика в его дата-центре или его VPS.
- Доступ по VPN + SSH-ключ.
- Из дома подключение к нодам заказчика — точно так же, как к Selectel.
- Никаких «домашних серверов», всё профессионально.

**Через год (3–5 заказчиков):**
- У каждого своя инфраструктура.
- `~/.ssh/config` с десятками хостов.
- Ansible-инвентарь по заказчикам.
- Git push в их Gitea-инстансы.
- Роль «внешнего DevOps» — без собственного железа.

## 7. Преимущества этой модели

| Преимущество | Как проявляется |
|---|---|
| **Безопасность администратора** | Домашний IP не светится в публичных логах заказчика |
| **Свобода** | Работа из любой точки мира, где есть интернет |
| **Разделение** | Локальные эксперименты не роняют прод, и наоборот |
| **Воспроизводимость** | Всё в git, можно клонировать инфру, нанять помощника |
| **Соответствие практикам** | Это стандарт enterprise DevOps |

## 8. Типичные ошибки

**«Поднять ещё одну ноду дома и включить в кластер»:**
Не рекомендуется. Домашний канал и uptime не соответствуют продакшену. Будет вечно «что-то отваливается, наверное мой NAT глючит».

**«Настроить DynDNS и ходить на домашний сервер»:**
Устаревший подход. В 2026 году есть VPN и облака.

**«Зачем VPN, если есть SSH-ключ»:**
Когда заказчик скажет «вот наш периметр, подключайся через WireGuard», наличие навыка работы с VPN будет преимуществом.

**«Купить IP в Selectel и ходить с него домой»:**
Возможно, но нецелесообразно. Selectel-нода — это уже удалённый хост с белым IP. Всё, что нужно, делается на ней.
