# Выбор стека под целевую архитектуру

**Время чтения:** ~6–8 минут
**Фаза:** 0 (вводная теория перед практикой)
**Цель:** осознанно выбрать стек и обосновать его заказчику.

---

## 1. Что строится

Целевая архитектура — **приватное облако для среднего бизнеса (SMB)** с собственной инфраструктурой, где ключевые боли:
- Безопасность (ФСТЭК, 152-ФЗ, audit-требования).
- Надёжность (отказы серверов, резервирование, RTO/RPO).
- Производительность (I/O bottlenecks, сетевые задержки).

Заказчик — **не стартап**, у него есть legacy (часто 1С, MSSQL, Hyper-V) и желание «причесать» или заменить. Бюджет средний — не FAANG, но и не «на коленке». Решения должны быть **воспроизводимыми, обслуживаемыми, документированными**.

## 2. Критерии выбора

| Критерий | Почему важен |
|---|---|
| **Воспроизводимость** | Развёртывание за часы, не за недели |
| **Изоляция сервисов** | Один сервис не должен ронять соседний |
| **Производительность I/O** | Базы, почта, файлы — основная нагрузка SMB |
| **Отказоустойчивость** | RTO ≤ 1 час, RPO ≤ 24 часа — baseline |
| **Простота автоматизации** | Ansible, не ручная настройка |
| **Лицензионная чистота** | Без GPL-сюрпризов в коммерческом продукте |
| **Предсказуемость** | Длинный цикл поддержки, стабильный API |

## 3. Почему именно Bastille + ZFS + PF + CARP

**Bastille (jails) — для изоляции сервисов.**

- Нативно для FreeBSD, не нужно тащить Docker.
- Снапшот ZFS = шаблон jail за миллисекунды.
- Декларативный `Bastillefile` (как Dockerfile, но нативнее).
- Десятки jail-ов на одной ноде без существенного расхода ресурсов.
- Управление через `bastille` CLI или удалённо через `bastille-remote`.

**Пример. Создание и клонирование jail:**

```bash
# Создать шаблонный jail с nginx
bastille create nginx 14.3-RELEASE 10.10.10.10
bastille pkg nginx install -y nginx
bastille template alexey/bsd-cloud

# Сделать snapshot и развернуть 5 копий за секунды
bastille stop nginx
zfs snapshot zroot/jails/nginx@template
for i in 1 2 3 4 5; do
    zfs clone zroot/jails/nginx@template zroot/jails/nginx-$i
    bastille start nginx-$i
done
```

**ZFS — для хранилища.**

- Встроенный snapshot/clone — база для бэкапов и шаблонов jail.
- `zfs send | zfs receive` — потоковая репликация на удалённую ноду.
- Самовосстановление через `scrub` (raidz1/2, mirror).
- Шифрование на уровне датасета.
- ARC в RAM даёт производительность, которой ext4+LVM не достичь.

**PF — для файрвола.**

- Простой читабельный синтаксис.
- Anchors — иерархия правил, удобно для многосервисных систем.
- Таблицы — для интеграции с sshguard.
- ALTQ (в 14.x) и netgraph — для шейпинга трафика.

**CARP — для отказоустойчивости.**

- Master/Backup IP-адреса, встроено в ОС, без отдельных демонов.
- Автоматический failover за 1–2 секунды.
- Работает на любом L2-сегменте (приватная сеть Selectel).

**Дополнительные компоненты стека:**
- **HAProxy** — L7-балансировка с health checks.
- **Ansible** — декларативный IaC, push-модель, идемпотентность.
- **Prometheus + Grafana + Loki + Alertmanager** — observability.
- **Gitea** — приватный репозиторий для конфигов (форк GitHub-экосистемы на Go).

## 4. Сравнение с «Docker + ext4 + iptables»

| Критерий | Bastille + ZFS + PF + CARP | Docker + ext4 + iptables |
|---|---|---|
| **Изоляция** | Нативная jail, минимальные накладные расходы | Namespaces + cgroups, слой overlayfs |
| **Снапшоты** | `zfs snapshot` — мгновенно, минимум места | Только вручную или внешние решения (Restic, Borg) |
| **Клонирование** | `zfs clone` — мгновенная копия | `docker commit` — пересборка слоёв, долго |
| **Хранилище** | ZFS, проверено 15+ лет | ext4 + LVM, нужен внешний snapshot-инструмент |
| **Репликация** | `zfs send/receive` нативно, по ssh | Ничего нативного, нужен Restic/Borg |
| **Файрвол** | PF, простой синтаксис | iptables — спагетти-правила, nftables — лучше, но сложнее |
| **Отказоустойчивость IP** | CARP, встроено | VRRP/keepalived, отдельный демон |
| **Автоматизация** | Bastillefile (читабельно) | Dockerfile + docker-compose.yml (есть индустрия) |
| **Экосистема готовых образов** | Ограниченно, нужно собирать | Docker Hub, тысячи готовых |
| **Порог входа для админа** | Средний (нужно знать FreeBSD) | Низкий (знакомо большинству) |
| **Воспроизводимость стенда** | Через Ansible + ZFS-реплика | Через Ansible + свежая установка ОС |
| **Лицензия** | BSD, можно форкнуть и закрыть | GPL в ядре, плюс Apache/MIT в Docker |

## 5. Когда НЕ этот стек

Честный разбор кейсов, где Docker+Linux выигрывает:

- **Kubernetes с 20+ нодами.** Тогда k3s на Linux-нодах, не Bastille.
- **Готовые коммерческие приложения в контейнерах.** Многие вендоры дают только Docker-образы.
- **Команда без опыта FreeBSD.** Найти FreeBSD-эксперта сложнее, чем Linux-админа.
- **AI/ML с GPU.** NVIDIA-драйверы и CUDA под Linux работают сильно лучше.
- **Большие объёмы Linux-only софта.** Специфические дистрибутивы для телекома, etc.

## 6. Почему гибрид (FreeBSD + Linux) — не страшно

Подход — **не** «всё на FreeBSD» или «всё на Linux», а **гибрид**:
- **FreeBSD** — базовая инфраструктура: ядро, сеть, хранилище, jail-ы.
- **Linux** — прикладные сервисы, где он сильнее: мониторинг, k3s, AI/ML, если потребуется.

Это даёт:
- Лучший инструмент под каждую задачу.
- Меньше vendor lock-in — можно мигрировать сервис с BSD на Linux и обратно.
- Демонстрация прагматизма заказчику: «не религиозный выбор ОС, а рабочее решение».

## 7. Как это объясняется заказчику

Ключевой аргумент:

> «Мы используем BSD-jail со снапшотами ZFS не потому что Docker неприятен, а потому что это даёт мгновенное клонирование сервисов, надёжную репликацию и лицензионную чистоту для вашего compliance. Балансировка и автоматизация — стандартные (HAProxy, Ansible), без vendor lock-in. По цене — лицензия FreeBSD = 0 ₽, оплачиваются только наше время и железо.»

Это уже не «настроил сервер», а **продуктовое позиционирование**.

## 8. Сравнение альтернативных стеков

| Стек | Когда применять | Плюсы | Минусы |
|---|---|---|---|
| **Bastille + ZFS + PF + CARP** | SMB-облако, файловые сервисы, почта, веб | Лицензия BSD, ZFS-преимущества, нет GPL-сюрпризов | Узкая ниша FreeBSD-экспертов |
| **Docker + ext4 + iptables + VRRP** | Классика, массовый рынок | Много готовых образов, легко нанять админа | Нет нативных снапшотов, GPL-вирусность |
| **Proxmox VE (KVM + LXC + Ceph)** | Универсальный хостинг | Готовый GUI, кластер из коробки | Linux, GPL |
| **OpenStack** | Крупные инсталляции, 10+ нод | Стандарт enterprise | Сложно, требует команду |
| **Harbor + Kubernetes** | Cloud-native приложения | Современный стек | Тяжело для SMB, нужен DevOps-отдел |
| **VMware vSphere** | Legacy enterprise | Работает, бренд | Уход Broadcom, дорого, нужна замена |
