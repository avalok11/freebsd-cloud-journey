## Изменение с 2026-10-27: выбыл fbsd-1-sel, появился fbsd-3-sel

Мастер-нода `fbsd-1-sel` перестала запускаться — в Selectel не хватает ресурсов
после массовой миграции компаний в дата-центр. `fbsd-ca-sel` и `fbsd-2-sel`
работают. Чтобы продолжить курс, разворачивается новая нода **`fbsd-3-sel`**,
которая занимает роль master'а.

Это unplanned-работа, но она даёт то, чего нет ни в одном учебном курсе:
**реальное восстановление master'а с собственной реплики** — механизм, который мы
построили в Фазе 1, впервые сработал по назначению.

Подробный план: [`00-fbsd-3-sel-provisioning.md`](./00-fbsd-3-sel-provisioning.md) —
Дни 0–1, роли нод на весь курс, сценарий возвращения `fbsd-1-sel` и фолбэк, если
Selectel не даст новый VPS.

### Роли нод на весь курс

| Нода | Роль | Фазы |
|---|---|---|
| `fbsd-ca-sel` | SSH CA: подпись ключей, CRL | 0.1 → 8 |
| `fbsd-3-sel` | **master**: ZFS-пул, источник репликации, jails, Bastille, bhyve; позже HA-мастер, Gitea, мониторинг | 1.5 → 8 |
| `fbsd-2-sel` | реплика ZFS, jump-only к `fbsd-3-sel`; позже HA-бэкенд | 1 → 8 |
| `fbsd-arm` (локально) | arm64-лаборатория: jails, PF, ZFS, Bastille, сравнение с amd64 | 0 → 8 |
| `deb-arm` (локально) | Linux-мост | 0 → 8 |
| `fbsd-1-sel` | **выбыла**; при возвращении — ре-сид либо второй HA-узел | — |

## План по неделям и дням (~6 ч/неделю)

### Неделя 1 — Новая нода, восстановление, Bastille
**Цель:** поднять `fbsd-3-sel`, вернуть стенду рабочее состояние, jail поднят и слушает HTTP.

- **День 0 (~3 ч) — Развёртывание `fbsd-3-sel`**
  - VPS в Selectel: FreeBSD 15.1 amd64, 2 vCPU / 2 ГБ RAM / 40 ГБ SSD, публичный IP; приватный адрес желательно `172.16.0.2` — тогда вся конфигурация Фазы 1 остаётся валидной без правок
  - Установка, sshd, закрытый root, баннер
  - Hardening по Фазе 0: PF ruleset из репо, sshguard, TOTP
  - Host-сертификат через `fbsd-ca-sel`, Host CA в `known_hosts` на всех нодах
  - ZFS: `zroot` → `zroot/tank` → `logs`/`repl`/`secure` (**`data` не создаём** — его создаст приём потока)
  - Команды: [`00-fbsd-3-sel-provisioning.md`](./00-fbsd-3-sel-provisioning.md) → «День 0»

- **День 1 (~2 ч) — Восстановление данных и смена ключа**
  - `fbsd-3-sel` становится jump-host'ом к `fbsd-2-sel` — реплика снова доступна
  - Восстановление `zroot/tank/data` с реплики: `zfs send -R` с `fbsd-2-sel` → `zfs receive` на `fbsd-3-sel`. **Это DR-сценарий: master восстановлен с собственной реплики**
  - Новый сервисный ключ `zfs_repl`: сгенерировать, подписать на CA, **отозвать старый** через CRL (первый реальный отзыв в курсе)
  - `from=` в principals-файле на реплике — привести к новому IP master'а (если адрес изменился)
  - Посеять маркер `/var/db/zfs-replication/last-snapshot` из фактического состояния реплики
  - Проверка сквозного цикла: `@repl-6` принят
  - Команды: [`00-fbsd-3-sel-provisioning.md`](./00-fbsd-3-sel-provisioning.md) → «День 1»

- **День 2 (~2 ч) — Bastille: установка и bootstrap**
  - `pkg install bastille` на `fbsd-3-sel`
  - В `bastille.conf` выставить `bastille_zfs_enable="YES"`, `bastille_zfs_zpool="zroot"`, `bastille_zfs_prefix="tank/jails"`. `bastille_zfs_enable` по умолчанию `NO` — без него jail'ы не будут датасетами и не получат снапшотов
  - `bastille setup storage` и `bastille setup loopback`. **`setup firewall` пока не запускаем** — добавим anchor'ы Bastille в наш `pf-ruleset.conf` сами, на Дне 3
  - **Bootstrap.** В FreeBSD 15 базовая система управляется через `pkgbase`, поэтому для тонких jail'ов:
    ```sh
    bastille bootstrap --pkgbase 15.1-RELEASE
    ```
    Классический `bastille bootstrap 15.1-RELEASE update` — workflow для jail'ов на FreeBSD 14.x. На 15.1 workflow другой, это надо учесть.
  - Проверка: `bastille list`, `zfs list zroot/tank/jails` — jail'ы должны лежать именно там, где мы сказали
  - **Артефакт:** вывод `bastille list` и `zfs list` в отчёте фазы

- **День 3 (~2 ч) — Первый jail с VNET**
  - `bastille create web nginx --release 15.1-RELEASE` — jail с nginx
  - VNET: jail получает адрес из заданной подсети, выход в интернет через NAT на хосте
  - В `pf-ruleset.conf` добавить то, что ожидает Bastille: `table <jails> persist`, `nat on $ext_if from <jails> to any -> ($ext_if:0)`, `rdr-anchor "rdr/*"`, `anchor "bastille/*"`, и `set skip on lo` вместо `set skip на $lo_if` (клонированный `bastille0` принадлежит группе `lo`)
  - Применить: `sudo pfctl -nf /etc/pf.conf && sudo pfctl -f /etc/pf.conf`
  - Проверить изнутри jail: `ping 8.8.8.8`, снаружи: `curl http://<ip-jail>/`
  - **Артефакт:** конфиг VNET + вывод проверок

### Неделя 2 — Шаблонизация, переносимость, изоляция
**Цель:** сервис описывается файлом; один и тот же файл работает на arm64 и amd64; изоляция jail'а от хоста подтверждена.

- **День 4 (~2 ч) — Bastillefile**
  - Переписать созданный вручную jail как **Bastillefile** — декларативное описание сервиса
  - Проверить, что `bastille create` из файла даёт тот же результат, что и ручная настройка
  - Зафиксировать: какие параметры (VNET, сервисы, пакеты) относятся к сервису, а какие — к хосту
  - **Артефакт:** `Bastillefile` типового веб-сервиса

- **День 5 (~2 ч) — Переносимость arm64 ↔ amd64**
  - Поднять Bastille на `fbsd-arm` (FreeBSD 15.1 arm64, локально в UTM) и развернуть **тот же** Bastillefile
  - Что должно совпасть: структура jail'а, пакеты, сетевые настройки, пути
  - Что НЕ совпадёт: `arch` в параметре `pkg` (FreeBSD:15:amd64 vs FreeBSD:15:aarch64), и, возможно, пути под данные
  - **Артефакт:** таблица различий arm64 ↔ amd64 — это и есть артефакт переносимости

- **День 6 (~2 ч) — Изоляция, снапшоты и клоны**
  - Jail не видит файловую систему хоста (кроме явно смонтированного) и не видит процессы хоста
  - Сеть: два jail'а не видят друг друга; выход в интернет — только через NAT
  - `bastille snapshot web before-change` → изменить файл в jail'е → `bastille zfs web rollback before-change` → отката нет
  - `bastille clone web web-clone` — клон, поменять hostname, запустить оба одновременно
  - **Артефакт:** результаты проверок в отчёте фазы

### Неделя 3 — bhyve и бенчмарк
**Цель:** честно сравнить изоляцию jail и полноценную виртуализацию на одинаковом железе.

- **День 7 (~2 ч) — bhyve с Debian**
  - bhyve работает **только на amd64** — на arm64 (M4 + UTM) вложенной виртуализации нет. Значит, только Selectel, то есть `fbsd-3-sel`
  - `pkg install vm-bhyve`, `vm-bhyve create` с Debian cloud image (не ISO-установка — на 2 vCPU это часы)
  - Консоль через serial, доступ к гостю с хоста
  - **Артефакт:** рабочая VM в `benchmarks/`

- **День 8 (~2 ч) — Бенчмарк jail vs bhyve**
  - Одинаковый workload: nginx, отдающий статику; `wrk -t4 -c100 -d30s`
  - Сравнить: время старта, потребление памяти, rps, размер на диске
  - Оговорка: обе платформы работают на 2 vCPU / 2 ГБ — сравнение честное только внутри этого стенда
  - **Артефакт:** `benchmarks/jail-vs-bhyve.md`

- **День 9 (~2 ч) — Финальный шаблон и автоматизация**
  - Собрать шаблон «nginx + postgresql + php-fpm» как Bastillefile
  - `bastille-automation.sh` — скрипт развёртывания сервиса от нуля до работающего jail'а
  - Сводный отчёт фазы, проверка чеклистов
  - **Артефакт:** `Bastillefile`, `bastille-automation.sh`, `phase-2-report.md`

## Известные риски и открытые решения

| Риск | Суть | Варианты |
|---|---|---|
| **Selectel не даст новый VPS** | Ресурсы в дата-центре кончились — `fbsd-1-sel` не запускается именно из-за этого. Новый VPS могут и не дать | Фолбэк: jails/Bastille → `fbsd-arm` (локально, arm64), bhyve → `fbsd-2-sel` (amd64, работает). Подробно — в [плане развёртывания](./00-fbsd-3-sel-provisioning.md) → «Фолбэк» |
| **Приватный IP новой ноды** | Если не `172.16.0.2`, то `from="172.16.0.2"` в principals-файле и упоминания адреса в документации перестают быть верными | (а) выбить `172.16.0.2` — тогда вся конфигурация Фазы 1 валидна без правок; (б) взять любой и поправить одну строку + документацию |
| **RAM под bhyve** | Гостю 512 МБ; на 2 vCPU / 2 ГБ — терпимо, на 1 vCPU / 1 ГБ было бы впритык | Рекомендуем 2 ГБ при создании VPS. Если выйдет 1 ГБ — VM придётся урезать до 256 МБ, а Debian ставить cloud image'ом |
| **pkgbase на FreeBSD 15** | Базовая система в 15.x управляется через `pkg`, workflow Bastille другой, чем на 14.x | Учесть при bootstrap: `bastille bootstrap --pkgbase 15.1-RELEASE` |
| **VNET и PF** | NAT-заглушка в ruleset закомментирована с Фазы 1; Bastille ждёт своих anchor'ов, которых у нас нет | Добавить `table <jails>`, `nat from <jails>`, `rdr-anchor "rdr/*"`, `anchor "bastille/*"` и `set skip on lo` в `pf-ruleset.conf` (День 3) |
| **Bastille на 15.1** | Поддержка официальная — Getting Started Bastille построен на свежей FreeBSD 15.1 | Риска нет, но документацию надо читать именно по 15.x |
| **bhyve только на amd64** | На M4 вложенной виртуализации нет, локально bhyve не запустить | Задача выполняется только в Selectel — на `fbsd-3-sel` |
| **Потерян приватный ключ `zfs_repl`** | Ключ лежал в `/root/.ssh/` на выбывшей ноде | CA жив — выпускаем новый ключ и **отзываем старый** через CRL. Это и есть штатный механизм Фазы 0.1 |
