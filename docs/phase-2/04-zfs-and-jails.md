# ZFS + jails: почему jail'у нужен ZFS

**Цель:** понять, что даёт размещение jail'а в ZFS-датасете и как из уже
сделанного в Фазе 1 получается миграция jail'а между хостами.

**Ключевой тезис.** Обычно jail — это каталог с файлами, снапшот которого требует
копирования. Jail в ZFS-датасете — это датасет, снапшот которого **мгновенный**,
потому что это CoW на уровне блоков. Плюс к этому работает уже настроенная в Фазе 1
машина `zfs send`/`zfs receive`.

## Jail = ZFS-датасет

```
zroot/tank/jails/releases/15.1-RELEASE     ← эталон
zroot/tank/jails/web                       ← jail (датасет)
zroot/tank/jails/web/root                  ← корень jail'а (точка монтирования)
zroot/tank/jails/web/root/usr              ← файловая система jail'а
```

Корень jail'а — датасет с `mountpoint` в `/usr/local/jail/<name>/root` (или там,
где задано в `bastille.conf`). Снапшот датасета = снапшот jail'а.

## Что это даёт

### 1. Мгновенный снапшот работающего jail'а

```sh
bastille snapshot web before-change
```

Это `zfs snapshot` под капотом. Снапшот **атомарен** — он фиксирует согласованное
состояние всех блоков, даже если в момент снапшота сервис пишет файлы. Сравните с
Docker: там для этого нужен `docker commit`, который сначала останавливает
контейнер, потом копирует слои. Или `docker export` — тоже копирование.

Отсюда прямое применение: **откат изменений в jail'е — это `zfs rollback`**, та же
команда, что мы отрабатывали в Фазе 1 на `zroot/tank/data`.

```sh
bastille zfs web rollback before-change
```

### 2. Мгновенный клон

```sh
bastille clone web web-clone
```

Это `zfs clone` — клон снапшота. Занимает секунды, места почти не жрёт (CoW).
Клон и оригинал работают **одновременно** и независимо — но это два независимых
датасета, а не форк процесса. Поменять hostname в клоне и поднять оба — валидный
сценарий, именно его мы будем проверять на Дне 6 Недели 2.

### 3. Миграция jail'а между хостами

Вот здесь Фаза 1 окупается напрямую. Jail — это датасет. Значит:

```sh
# на исходном хосте
zfs snapshot zroot/tank/jails/web@for-migration
zfs send zroot/tank/jails/web@for-migration \
  | ssh zfs-repl@<target> 'zfs receive zroot/tank/jails/web'
```

Это **тот же механизм**, который мы строили для репликации данных в Фазе 1: сервисная
учётка `zfs-repl`, `force-command` с `zfs receive`, `from=`-ограничение, `zfs allow`
вместо sudo. Всё то же самое, только в потоке едет не пользовательский датасет, а
rootfs jail'а.

Что нужно доработать для этого сценария (в Фазе 2 не делаем, но фиксируем):
- jail на целевой ноде должен быть создан заранее — `zfs receive` создаст датасет,
  но не создаст jail'а
- `zfs allow` на replica сейчас разрешает операции только с `zroot/tank/repl` —
  для приёма jail'а понадобится ещё один датасет в списке разрешений
- `from="172.16.0.2"` останется тем же — master как источник миграции

Это хорошая иллюстрация: ограничение доступа, настроенное в Фазе 1, **переиспользуется
для новой задачи без изменений** — меняется только имя датасета-приёмника.

### 4. Квотирование и учёт места

Jail-датасет — обычный датасет, значит работают:

```sh
zfs set quota=1G zroot/tank/jails/web
zfs set reservation=512M zroot/tank/jails/web
```

На нашем стенде (28 ГБ на `zroot`, из них занято под систему и под `tank/*`) квота
на каждый jail — обязательная гигиена, иначе один сервис съест пул.

### 5. Сжатие и atime

Наши `compression=lz4` и `atime=off` на `zroot/tank` наследуются в jail-датасеты
(свойства ZFS наследуются от родителя). Текстовые файлы внутри jail'а будут
сжиматься — для конфигов и логов это бесплатная экономия.

## Делегирование датасетов внутрь jail'а

Отдельная механизм, не путать с «jail лежит в датасете».

`zfs jail` / `zfs unjail` позволяют **отдать** jail'у целое поддерево датасетов:

```sh
zfs create zroot/tank/jails/web/data
zfs set jailed=on zroot/tank/jails/web/data
zfs jail web zroot/tank/jails/web/data
```

После этого jail администратор может внутри себя монтировать, создавать дочерние
датасеты, делать снапшоты — но **только в пределах отданного поддерева**.

Условия:

| Параметр jail'а | Значение | Зачем |
|---|---|---|
| `allow.mount` | `1` | разрешить монтирование |
| `allow.mount.zfs` | `1` | разрешить операции ZFS внутри |
| `enforce_statfs` | `< 2` | иначе jail увидит статистику всех датасетов пула |

Зачем это: у jail'а появляется **своё хранилище** с квотами и снапшотами, без
права на весь пул. Для сценария «PostgreSQL в отдельном jail'е с своим
квотированным хранилищем» — ровно то, что нужно.

## Сравнение с Docker

| | Jail в ZFS | Docker |
|---|---|---|
| Форма «образа» | датасет (clone из релиза) | tarball слоёв |
| Снапшот состояния | `zfs snapshot` — мгновенно, атомарно | `docker commit` — копирование, с остановкой |
| Клон | `zfs clone` — CoW, почти без места | `docker commit` + push/pull — копирование |
| Квота на контейнер | `zfs set quota` на датасет | `--storage-opt size=` (thin pool) |
| Миграция на другую ноду | `zfs send/receive` — тот же поток, та же учётка | registry + pull |
| Слои | нет, только CoW | да, слои с diff'ами |

Принципиальная разница: Docker экономит место за счёт **разделяемых слоёв** и
расплачивается за это невозможностью мгновенного снапшота состояния. ZFS
экономит место за счёт **CoW** — и снапшот, и клон бесплатны.

## Практика: что проверим

```sh
# jail — датасет?
zfs list -o name,used,refer,mountpoint zroot/tank/jails

# снапшот jail'а
bastille snapshot web before-change
zfs list -t snapshot -r zroot/tank/jails

# откат: изменить файл в jail'е, откатить снапшот, убедиться
bastille cmd web sh -c 'echo changed > /root/inside-jail.txt'
bastille cmd web cat /root/inside-jail.txt
bastille zfs web rollback before-change
bastille cmd web cat /root/inside-jail.txt     # файла нет — откат сработал

# клон: два jail'а одновременно
bastille clone web web-clone
bastille start web-clone
```

## Вывод

Размещение jail'а в ZFS — не «для красоты», а ради трёх вещей: мгновенного
снапшота, мгновенного клона и переноса jail'а между хостами тем же инструментом,
который в Фазе 1 уже настроен и проверен. Наш выбор FreeBSD+ZFS+Bastille даёт
всё это из коробки, а Docker на Linux за каждый из этих пунктов предлагает
компромисс.
