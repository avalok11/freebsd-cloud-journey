# Jails: как устроена изоляция в FreeBSD

**Цель:** понимать, что именно jail изолирует и что не изолирует — чтобы не строить
безопасность на «jail же вроде как в песочнице».

**Ключевой тезис.** Jail — это **не процесс и не программа, а объект состояния ядра**.
Ядро FreeBSD знает про jail'ы на первом уровне: у каждого свой сетевой стек, своя
таблица IPC, свои учётные данные, свой набор sysctl. Docker собирает похожую
изоляцию из namespace'ов Linux, а jail — это примитив в самом ядре, написанный под
TrustedBSD и отдельно аудированный.

## Что изолирует jail

| Подсистема | Изолирована | Комментарий |
|---|---|---|
| Сетевой стек | ✅ (при VNET) | Свои интерфейсы, маршруты, правила firewall, свой loopback |
| IPC | ✅ | Свои очереди сообщений, семафоры, shared memory |
| Учётные данные | ✅ | Свой uid/gid, группы, `securelevel`, capabilities |
| Таблица файловых дескрипторов | ✅ | Свои fd, не видны процессам хоста |
| `sysctl` | ✅ | Своё поддерево параметров ядра |
| Routing table | ✅ (при VNET) | Своя таблица маршрутизации |
| Устройства | ⚠️ частично | Управляется через `devfs.rules`, jail'у открывают только нужное |
| Файловая система | ❌ | Это **chroot**, а не отдельная ФС. Jail ограничен правами на каталог |
| **Ядро** | ❌ | Общее с хостом. Эксплойт ядра = выход из jail |

Последняя строка — главное. Jail и Docker **в одном классе по риску выхода**: оба
делят ядро с хостом. Разница в том, что jail — примитив, спроектированный и
проверяемый как таковой, а namespace'ы Linux собираются из универсальных
механизмов, не спроектированных специально для изоляции.

## Как это работает технически

Создание jail'а — три системных вызова:

```
jail_set(2)      # создать jail, получить jid
jail_get(2)      # получить параметры существующего jail'а
jail_attach(2)   # ввести процесс в jail
```

Процесс входит в jail через `jail_attach(2)` — после этого он принадлежит jail'у
на уровне ядра, и ограничения применяются к каждому его syscall'у, а не
проверяются «на входе».

Управление снаружи:

```sh
jls                    # список jail'ов: jid, path, IP, статус
jexec <jid> <cmd>      # выполнить команду внутри jail'а
```

### Вложенные jail'ы

Поддерживаются: jail внутри jail'а. Параметр `jail` в `jail.conf` задаёт родителя.
Для нас это пока не актуально, но механизм полезен, когда один jail'у нужно
изолировать от соседа — без отдельной VM.

### Видимость процессов

По умолчанию процесс хоста **видит** все процессы jail'ов, а процесс jail'а —
только свои. Управляется параметрами:

```sh
sysctl security.bsd.see_jail_proc=1     # хост видит процессы jail'ов
sysctl security.bsd.see_jail_sysctl=1   # хост видит sysctl jail'ов
```

Обе переменные читаются **изнутри** jail'а и регулируют, что этот jail видит
снаружи. Для нашей задачи (сервисный доступ, администрирование) оставляем как есть,
но знать полезно: если Jail'у не нужно видеть хост — можно закрыть.

## Сравнение с Linux

| Свойство | FreeBSD jail | Docker (runc) | LXC |
|---|---|---|---|
| Уровень в ядре | Первоклассный примитив | namespace'ы (UTS, IPC, mount, PID, net, user) | те же namespace'ы + cgroups |
| Файловая система | chroot | overlayfs поверх образа | chroot/примонтированный каталог |
| Сеть | VNET — свой стек ядра | bridge/veth, изоляция на сетевом уровне | veth |
| Снапшот состояния | ZFS-снапшот датасета — мгновенно | `docker commit` — копирование слоёв | снапшот ФС — медленно |
| Провен аудитом | Да (TrustedBSD) | Нет, namespaces — универсальный механизм | Нет |
| Ресурсные лимиты | `rctl` (rlimit + cpuset) | cgroups v2 | cgroups |
| Выход через баг в ядре | Возможен | Возможен | Возможен |
| Выход через баг в рантайме | Нет (рантайма нет) | Нет | Нет |

Ключевое отличие, которое важно для нас: **у jail'а нет рантайма**. Нет ни
`runc`, ни `containerd`, ни shim-процессов. Jail — это ядро и данные. Отсюда
следствия: запуск jail'а занимает десятки миллисекунд (создать датасет + войти в
jail), а «образ» — это ZFS-датасет, а не tarball слоёв.

### Чего jails не умеют (а Docker умеет)

- Готовых образов в реестре нет — образ jail'а собирается на месте
- Нет автоматической оркестрации и декларативных манифестов из коробки (Bastille
  это частично закрывает)
- `docker run` одной командой не существует — есть `bastille create`

## Практика: посмотреть на jail

```sh
# список jail'ов
jls

# параметры конкретного jail'а
jls -v

# sysctl, доступные внутри jail'а
jexec <jid> sysctl -a

# параметры ядра про саму возможность jail'ов
sysctl kern.features.jail
```

## Вывод

Jail'ы — нативная изоляция FreeBSD: дёшево, быстро, без слоёв пользовательского
пространства, с бесплатными снапшотами от ZFS. Цена — общий с ядром хост и
отсутствие готовых образов. Для наших сценариев (веб-сервисы, изолированные
приложения на одном хосте) это ровно то, что нужно, и именно поэтому мы выбрали
Bastille, а не Docker.
